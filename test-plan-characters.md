# План ручного тестирования: Priest, Redneck, Rider (PIE)

Раскладка клавиш — по коду (`ABaseCharacter`/`ARedneckCharacter`/`ARiderCharacter`, проверьте в Project Settings → Input, если меняли): ЛКМ — атака/бросок, ПКМ — прицел (удержание), C — присед (тоггл), Left Alt — спринт (тоггл), Space — прыжок / дыхание носом в панике / спешиться при верховой езде, E — взаимодействие/подбор / QTE побега из капкана, 1-4 — quick-слоты, колесо мыши — переключение слота, T — фонарик (Redneck/Sibling), F — охотничий глазомер (Redneck) / посадка верхом (Rider), Q — выпить самогон (Redneck) / удар кадилом (если в руке Censer).

Общий принцип: сначала база (общая для всех трёх — она живёт в `ABaseCharacter`), потом уникальная механика героя в изоляции, потом пересечения внутри одного героя, потом герой × монстр, потом герой × мир. Если шаг не проходит — не чините на ходу, фиксируйте отдельной задачей Claude Code по вашему шаблону ТЗ (см. `CLAUDE.md`) и отмечайте в таблице стабилизации.

## Фаза A — база (`ABaseCharacter`), проверить на КАЖДОМ из трёх героев

1. Спавн героя — стоит, не падает сквозь пол, камера корректна.
2. Движение WASD, поворот камерой — без рывков.
3. Спринт (Alt) вкл/выкл — скорость меняется (300→600 по умолчанию), повторный Alt возвращает обычную скорость.
4. Присед (C) вкл/выкл во время покоя — работает.
5. **Присед во время спринта** (не через Alt, а прямо на бегу) — спринт должен автоматически отмениться (см. `SprintSystemTest.cpp` — уже покрыто тестом, но проверьте глазами один раз).
6. Прицеливание (удержать ПКМ) — появляется крестик по центру экрана, цвет меняется в зависимости от цели (белый/красный/зелёный на монтируемом монстре).
7. Бросок предмета (ЛКМ во время прицела) — если в руке есть Holy Item, улетает в точку прицела.
8. Interact (E) — подбор предмета с пола (Candle/Censer в зависимости от уровня), предмет оказывается в руке.
9. Переключение quick-слотов (1-4 и колесо мыши) — активный слот подсвечивается на HUD.
10. Получение урона — здоровье снижается на HUD, при 0 — смерть/рэгдолл.
11. Bear Trap: наступить на капкан — персонаж прикован, начинается QTE (частые E), после выполнения — свободен, капкан уничтожается.
12. Паника/дыхание: получить атаку монстра, вызывающую нокдаун — появляется индикатор дыхания, Space в такт (нос) снижает панику, невпопад/пауза (рот) — увеличивает; по завершении либо встаёт, либо особождается принудительно.

## Фаза B — уникальная механика героя в изоляции

### Priest
1. Стартовая свеча (если `StartingCandleClass` задан) — заспавнена и сразу в руке при `BeginPlay`.
2. Держит зажжённую свечу в любой руке → персонаж автоматически приседает (`OnHeldItemsChanged`), встаёт при выбрасывании последней свечи.
3. Свеча создаёт зону защиты — монстр рядом получает периодический урон/не подходит (см. `AHolyLightZone`/`IsLocationProtected`).

### Redneck
1. Фонарик (T) — вкл/выкл, батарея тратится на HUD, гаснет сам при 0.
2. Охотничий глазомер (F) — замедление мира, разметка шагов до цели, кулдаун после окончания; во время слепоты/закрытых глаз маркеры переходят в "мысленный след" (`SetMentalTrailActive`).
3. Самогон, Tier 1 (Q, из quick-слота) — баф активен `MoonshineDuration` сек, буст спринта, после — кулдаун `MoonshineCooldown`.
4. Самогон, Tier 2 "Таран" (удержать ПКМ + ЛКМ **при активном бафе**) — рывок в направлении прицела; **без бафа** то же сочетание должно давать обычный бросок предмета, а не рывок (см. `BullsChargeComboTest.cpp`).
5. Таран/пассивный навал на бегу с активным бафом — столкновение с монстром станит его, со случайным объектом — наносит урон.

### Rider
1. Стартовое кадило (если `StartingCenserClass` задан).
2. Кадило-Q — удар кадилом (`SwingHeldCenser`), если оно в руке.
3. Верховая езда (F, прицел на монстра в зелёной подсветке крестика) — посадка на монстра, камера/коллизия адаптируются.
4. Управление монстром под верхом — WASD реально двигает монстра, без рывков/вращения (см. Фазу C.3 — известный риск).
5. Спешивание (Space) — плавный слезание, персонаж откидывается назад.
6. Получение урона во время верховой езды — принудительно сбрасывает с монстра (`OnKnockedOffMount`), с более сильным отбросом, чем обычное спешивание.

## Фаза C — пересечения ВНУТРИ одного героя (самое частое место регрессий)

Проверить на каждом герое то, что применимо:

1. Прицеливание + присед одновременно — не ломает ни то, ни другое.
2. Паника (дыхание) НАЧАЛАСЬ во время: спринта / приседа / прицеливания / удержания предмета — что происходит с этими состояниями? Ожидание: паника блокирует активные действия корректно, а не оставляет персонажа в подвешенном состоянии.
3. **Rider: посадка верхом во время паники / во время капкана / во время прицеливания** — сейчас в коде НЕТ явной защиты от одновременного мониторинга этих состояний, это либо сработает нормально, либо обнаружит дыру. Отдельно проверить: капкан ловит персонажа, УЖЕ сидящего верхом — что происходит с обоими акторами.
4. **Redneck: Rage Dash в момент нокдауна/паники** — не должен запускаться, если персонаж выведен из строя.
5. Смена quick-слота во время прицеливания/паники — не должна прерывать текущее действие непредсказуемо.
6. Общие клавиши: пока держите ПКМ (прицел) — нажмите Q (Redneck) и F (Rider/Redneck) — правильная функция должна сработать, а не обе/не та.

## Фаза D — герой × монстр

Пройти на каждом герое (Patrol → Stalk → Chase → атака монстра — спровоцировать по очереди):

1. Монстр патрулирует, герой далеко — монстр не реагирует.
2. Герой входит в радиус — монстр переходит в Chase, преследует корректно (не застревает, не крутится на месте).
3. Герой в тени/вне поля зрения — монстр теряет цель, возвращается к патрулю.
4. Eye Peek: закрыть глаза рядом с монстром и подглядывать (держать ПКМ) — монстр должен ловить это по-разному в зависимости от исхода (см. `EyePeekRiskTest.cpp` — 5 сценариев, уже автоматизировано, но полезно увидеть глазами хотя бы раз на каждом герое).
5. Получение урона от монстра — здоровье падает, при летальной атаке — смерть.
6. **Rider отдельно: сесть верхом на монстра, который до этого патрулировал/преследовал** — движение монстра должно полностью перейти под управление игрока, без рывков (ключевая проверка из плана стабилизации, Этап 1).
7. Монстр в дневное время убегает в тень (если тестируете достаточно долгую сессию/ускоренный день) — не атакует, пока прячется.

## Фаза E — герой × мир

1. Смена дня/ночи (`ADayNightManager`) — освещение меняется плавно, монстр реагирует на переход (`OnDawnStarted`/`OnDayStarted`/`OnNightStarted`).
2. Priest/Rider: зона святого света (`AHolyLightZone`) — монстр внутри получает периодический урон, герой не задет.
3. Капкан, расставленный заранее — герой, идущий обычным шагом/спринтом/верхом (Rider), по-разному в него попадает или нет (верхом капкан вообще должен ловить? — проверить, что не ловит несуществующего пешехода под монстром).
4. Подбор/бросок предметов рядом с препятствиями — предмет не проваливается сквозь geometry, не залипает.

## Как фиксировать результат

На каждый непройденный пункт — отдельная задача Claude Code по формату из `CLAUDE.md` (контекст → что сделать → что не трогать → критерий готовности), НЕ куча правок за один заход. После фикса — если пункт из Фазы C или D (пересечение состояний) — оформить как Automation Test по образцу `EyePeekRiskTest.cpp`/`BullsChargeComboTest.cpp`, чтобы регрессия не вернулась молча. Пройденные пункты — повод перенести механику в «стабильные» в реестре `CLAUDE.md`.
