# Наездница — спецификация

Персонаж **Наездница** (`ARiderCharacter`) — единственный герой, способный оседлать монстра и управлять им.
Её оружие — святое кадило на цепи; защита — огонь кадила и аварийный «святой взрыв».
Код сосредоточен в `Source/MyCharacters/Public|Private/RiderCharacter.*`,
`MountRiderComponent.*`, `Components/RiderHookComponent.*`, `Components/InkVisionComponent.*`,
`ResourceStockpileComponent.*`.

## 1. Цель

Почему это нужно: Наездница — высокорисковый герой, чья сила напрямую зависит от управления монстрами.
Верхом она сильна и мобильна, но потеря монстра (сброс, капкан, взрыв) переводит её в уязвимое пешее состояние с уменьшенной защитой кадила.
Дизайн-намерение: каждая способность либо усиливает езду, либо служит страховкой при потере монстра.

## 2. Терминология

| Термин | Значение |
|---|---|
| **Верхом** / **mounted** | `bIsMounted == true`, `MountedMonster` ненулевой |
| **Пешком** | `bIsMounted == false` |
| **БАК** | `AHolyItem::FuelRemaining` / `MaxFuel` — топливо в самом кадиле |
| **РЕЗЕРВ** | `ARiderCharacter::OilReserve` (`UResourceStockpileComponent`, потолок 10) — запасное масло |
| **Защитный радиус** | Радиус святого поля кадила — `HolyAuraRadius`=220 верхом, `FootProtectionRadius`=180 пешком |
| **Святой взрыв** | Экстренная абилка X — прыжок + убийство всех монстров в радиусе |
| **Крючок** | `AHookPoint` — дизайнерски расставленные точки привязки, доступны только верхом |
| **Чернильное зрение** | `UInkVisionComponent` — временное зрение силуэтами без риска обнаружения, безопасно так же, как «Воспалённое зрение» Священника |
| **Чернила (не реализовано)** | Задуманный расходуемый ресурс, которым должно быть ограничено чернильное зрение — по аналогии с РЕЗЕРВ/БАК масла или `MoonshineStock` Реднека. Сейчас способность ограничена только `VisionDuration`/`VisionCooldown`, без отдельного конечного запаса |

## 4. Недочёты, допущения, важно

**допущение:** `AHookPoint` — маленький актор, прицеливание в него верхом (когда тело монстра мешает углу) неудобно. Полировка прицела — отдельная будущая задача, не блокирует.

**допущение:** Капкан не ловит игрока, который уже сидит верхом — монстр наступает на него как на обычный объект. Баг замечен, зафиксирован, НЕ исправлен (низкий приоритет).

**допущение:** Визуальный канат/цепь между рукой и кадилом (`UCableComponent`) — механика готова, но косметическая цепь пока не нарисована.

**допущение:** Анимация вставания (`GetUpAnimation`) после паники — пустая заглушка, вставание визуально мгновенное. Не блокирует геймплей.

**недочёт:** Ограничение посадки по углу зрения монстра («сесть только со спины/сбоку») — не реализовано. Сейчас `TryMount()` пускает с любого направления.

**недочёт:** Расход масла из резерва (`OilReserve`) и экономика пополнения кадила в поле — базовая (ручная R-доливка). Автоматическое пополнение и подбор масла на уровне — будущие задачи.

**важно:** Применение `UResourceStockpileComponent` совместно с `APriestCharacter` (запас свечей) — один и тот же компонент, разные конфигурации. Не менять сигнатуру компонента без учёта обоих потребителей.

**важно:** `AHolyItem::LightUp()` имеет гейт `FuelRemaining <= 0` — кадило с пустым баком не зажигается. Это намеренно, не баг.

**недочёт:** Чернильное зрение задумано как способ ориентироваться в темноте с закрытыми
глазами, зависящий от расхода ресурса «чернила» — по аналогии с тем, как у Наездницы уже
есть двухуровневый ресурс масла (РЕЗЕРВ/БАК, §6.2) и как у Реднека `MoonshineStock`
ограничивает личный баф. Сейчас в коде (`UInkVisionComponent`) такого ресурса нет вообще —
ограничение целиком времянное: `VisionDuration` (10с) + `VisionCooldown` (15с), тот же
паттерн, что у Воспалённого зрения Священника (`UVisionFireSourceComponent`), у которого
тоже нет расхода ресурса. Нужно решить при постановке ТЗ: единицы измерения «чернил»,
начальный/максимальный запас, тратится ли фиксированная порция за один тоггл или
постепенно по ходу активного действия, и как «чернила» пополняются (ручная доливка как
масло, подбор предметов, или что-то ещё). См. §8.5.

**недочёт:** место встречи со Священником, на которой Наездница получает кадило в подарок,
не зафиксировано — ни конкретной сюжетной сцены, ни точки на карте. Сейчас это просто
конфигурация уровня (`StartingCenserClass`), без своей сцены вручения. См. §6.1.

**недочёт:** «Вращение кадила над головой» как отдельное, управляемое игроком действие
(отпугивание по площади ценой быстрого расхода масла) — не реализовано. Не путать с уже
существующей постоянной визуальной позой «лассо» (`AHolyItem::Tick()`, включается
автоматически верхом при зажжённом кадиле, без своего расхода топлива). См. §6.6.

## 5. Монтирование (верховая езда)

Почему это нужно: монстр — и оружие, и щит Наездницы. Верхом она контролирует угрозу, направляет её и использует как транспорт. Потеря монстра = потеря основного преимущества.

### 5.1 Посадка (`TryMount`)

- Обнаружение цели — через прицел (`ABaseCharacter::TraceAimTarget()`), тот же луч, что и для HUD-крестика. Монстр в прицеле → крестик зеленеет → F → посадка.
- `CanMountMonster()` проверяет **все** условия (провал любого — отказ с перечислением причин):
  - Игрок не в панике (`!bIsPanicking`)
  - Игрок не в капкане (`!bIsTrapped`)
  - Монстр жив (`Health > 0`, `bCanBeMounted`, `!bIsBeingRidden`)
  - Дистанция ≤ `MountDistanceThreshold`=450
- При успехе: игрок прикрепляется к `GetMesh()` монстра, отключается собственная Pawn-коллизия, `bIsMounted = true`, `ABaseMonster::bIsBeingRidden = true`.
- Высота посадки = `GetScaledCapsuleHalfHeight()` монстра + `MountRiderHeightBuffer`=30, вычислена от меша (не от кости), чтобы не зависеть от ориентации отдельных костей.

### 5.2 Управление верхом

- Движение монстром идёт через `ABaseMonster::RequestMoveToActor()/RequestMoveToLocation()` — единственная точка входа, все старые прямые вызовы `MoveTo` переведены на неё (Фаза 0 роадмапа).
- Анимация езды: `AnimGraph` `BP_Unarmed` через `Blend Poses by bool` по `IsMounted()` → воспроизводит `MountedRidingAnimation` (ссылка на `UAnimSequence`, назначается в BP defaults, `nullptr` = нет позы верхом).

### 5.3 Спешивание

- **Добровольное** (Space) → `Dismount()`: отсоединение, восстановление коллизии/движения/камеры, `LaunchCharacter` назад/вверх, `ABaseMonster::OnDismounted()`.
- **Принудительное** (удар по игроку верхом) → `OnKnockedOffMount()` → `HandleKnockedOffMount()`: то же что Dismount, но с `MountKnockOffForce`=600 (сильнее добровольного 300), без паники (паника при сбросе с монстра явно подавлена в `ABaseMonster`).

### 5.4 Капкан на монстра

- `ABearTrap::OnTriggerOverlap()` ловит монстра, если на нём сидит игрок: монстр замирает на `RiddenMonsterHoldDuration`=3с → `Dismount()` → капкан уничтожается. Пешая ветка без изменений.

## 6. Кадило на цепи

Почему это нужно: кадило — единственное оружие Наездницы. На ногах — факел/щит, верхом — активное оружие с взмахом и взрывом. Асимметрия радиуса и возможностей создаёт стимул держаться верхом.

### 6.1 Стартовое кадило

Кадило — постоянный предмет Наездницы на весь забег, получаемый по сюжету в подарок от
Священника при встрече с ним.

`StartingCenserClass` — опциональный класс `AHolyItem`. Если задан в BP, `BeginPlay()` спавнит кадило и автоматически подбирает его (подарок Священника по сюжету). По умолчанию — `None` (дизайнер может не выставлять).

**Открытый вопрос:** где именно по сюжету/на карте происходит эта встреча с Священником —
не определено. Сейчас `StartingCenserClass` — просто флаг конфигурации уровня (спавнится в
`BeginPlay()` того уровня, где выставлен), без отдельной сценарной сцены вручения. Нужно
решить: это конкретная катсцена/диалог в конкретной локации Акта, или кадило просто лежит
на уровне как подбираемый предмет без явной сцены встречи.

### 6.2 Экономика топлива (двухуровневый ресурс)

```
РЕЗЕРВ (OilReserve):   целые единицы, потолок 10, HUD-слот "Oil" (index 2, key "3")
БАК    (FuelRemaining): дробное float, потолок MaxFuel, отображается в HUD кадила
```

- **R** → `RefillCenser()`: переливает `min(остаток резерва, свободное место в баке)`, после доливки вызывает `LightUp()` (если кадило было потушено — зажигается обратно).
- **C** → `ToggleCenser()`: переключает между «потушено на поясе» / «зажжено в руке». Оба перемещают предмет между сокетами самостоятельно.
- `LightUp()` — гейт: `FuelRemaining <= 0` → не зажигается. Автодозаправка при зажигании убрана намеренно.
- Пассивный расход (`FuelDrainRate`, Tick()) идёт всё время, пока кадило зажжено, независимо
  от того, атакует кто-то или нет. Как только бак опустошается до 0 — `Extinguish()`
  вызывается автоматически, `bIsLit = false`, кадило гаснет само и немедленно перестаёт
  отпугивать монстров (все три защитных пути — толчок ауры, взмах, AI-Stalk — читают `bIsLit`, §6.3, §6.5).
- Пополнение РЕЗЕРВА сейчас только ручное (нет подбора масла на уровне) — периодически
  находимые канистры/масло на локациях заявлены как задумка, но не реализованы (см. §4).

### 6.3 Защита (щит): асимметрия верхом/пешком

| Состояние | Радиус | Физический толчок (`CenserPushbackForce`) | Взмах (ПКМ+ЛКМ) |
|---|---|---|---|
| Верхом | `HolyAuraRadius`=220 | ✅ | ✅ (тратит 1 ед. топлива) |
| Пешком | `FootProtectionRadius`=180 | ❌ | ❌ |

Монстры в `Stalk`-состоянии держатся на границе света (`ABaseMonster::IsProtectedByHeldItem()`), проверяет `bIsLit` — потушенное кадило не даёт защиты.

**Пока кадило горит — настоящая атака невозможна.** И верхом, и пешком зажжённое кадило
не даёт монстру провести полноценный урон/панику внутри своего радиуса (`bIsLit` гейтит
всю защитную цепочку, §6.5). Но сам радиус защиты небольшой, особенно пешком
(`FootProtectionRadius`=180) — поэтому монстр всё ещё может **пихнуть**/задеть персонажа,
просто без настоящего попадания:

**Удар по ногам** (пешком, раз в `LegSwipeCooldown`=3с):
- Монстр в радиусе → бросок `LegSwipeChance`=50% → лёгкий толчок без паники + утечка `LegSwipeFuelSpill`=5 топлива + `LegSwipeExtinguishChance`=20% шанс тушения.
- При тушении: `bIsAwaitingLegSwipeRelight` защищает от немедленного добивания; через `LegSwipeRelightDelay`=1с автоматически зажигается (если топливо ещё есть).
- Утечка топлива — та же идея «масло может частично разлиться», случайная, не фиксированная: `LegSwipeFuelSpill`=5 расходуется гарантированно при толчке, а полное тушение (а не просто частичная утечка) — отдельный, тоже случайный `LegSwipeExtinguishChance`=20% бросок поверх.

**Недочёт/открытый вопрос:** верхом (строка «Физический толчок ✅» в таблице выше) толчок
идёт в обратную сторону — кадило отталкивает монстра (`CenserPushbackForce`), без утечки
топлива для Наездницы. Аналога «монстр пихает Наездницу и проливает масло» верхом нет —
не решено, нужен ли он, или асимметрия (только пешком есть риск пролить масло) — осознанное
решение дизайна.

### 6.4 Взмах (верхом, ПКМ+ЛКМ)

Переиспользует хук `TryHijackAttackPress()` — тот же перехват атаки, что у Rage Dash Реднека. Трата 1 ед. топлива за использование; если топливо кончается в момент взмаха — кадило гасится сразу. Монстр при прямом попадании — отброс (`ApplyKnockback`), не мгновенная смерть (убийство только у «Святого взрыва»).

### 6.5 Дополнительные баги, исправленные в рамках этой механики

- `CheckAuraProximity()`, `PerformMeleeSwing()`, `IsProtectedByHeldItem()` — все три не проверяли `bIsLit`; исправлено. Потушенное кадило больше ни в одном из этих путей не даёт защиты.
- `ABaseMonster::OnCapsuleHit()` ветка «наскок» не проверяла `IsTargetInLight(Player)` — монстр мог бить прямо в свете. Исправлено одной строкой `if (IsTargetInLight(Player)) return;`.

### 6.6 Вращение над головой — задумано, не реализовано

Почему это нужно: помимо прицельного Взмаха (§6.4, разовое действие с чётким расходом
топлива), задумано отдельное действие — Наездница раскручивает кадило над головой,
отпугивая монстров вокруг себя по площади, пока действие активно, ценой быстрого расхода
масла.

**Не путать с уже существующим «лассо»:** в коде уже есть постоянная анимация вращения
кадила (`AHolyItem::Tick()`, «lasso» swing) — но это **чисто визуальная поза**, включается
автоматически самим фактом «верхом и зажжено» (`IsMounted() && bIsLit`), не завязана на
отдельный ввод и не имеет собственного расхода топлива сверх обычного пассивного
`FuelDrainRate`. Задуманное «вращение над головой» — наоборот, **активное, по требованию
игрока** действие (отдельная клавиша/удержание), которое должно:
- отпугивать монстров по радиусу (ближе по эффекту к пассивному толчку ауры, §6.3, но,
  видимо, сильнее/шире, раз заявлено отдельной способностью);
- расходовать топливо **значительно быстрее**, чем обычный пассивный `FuelDrainRate` —
  разменивая широкую защиту на время, которое кадило после этого сможет гореть.

**Открытые вопросы:** отдельная клавиша или удержание существующей (ПКМ без ЛКМ?); радиус
действия и сила отпугивания/толчка относительно `CenserPushbackRadius`/`CenserPushbackForce`
обычной ауры; доступно ли только верхом (как Взмах) или и пешком тоже; точный множитель
расхода топлива в секунду.

## 7. Крючки (хук-граппл)

Почему это нужно: крючки дают Наезднице вертикальное убежище, недоступное наземным монстрам. Доступны только верхом — так они остаются наградой за управление монстром, а не заменой ему.

### 7.1 Принцип работы

- `AHookPoint` — дизайнерски расставленные акторы. Доступны только через прицел (`TraceAimTarget()`) верхом.
- **F** (контекстная диспетчеризация `OnMountOrHookPressed()`):

| Текущее состояние | Действие по F |
|---|---|
| Не верхом | `TryMount()` |
| Верхом, прицел на `AHookPoint`, дистанция ≤ `HookGrappleRange`=800 | `TryGrapple()` |
| Верхом, прицел не на крючок | no-op |
| Висит на крюке | `DropFromHook()` |

### 7.2 `TryGrapple()`

1. `Dismount()` текущего монстра (монстр свободен, уходит в патруль).
2. Телепорт игрока к позиции `AHookPoint`.
3. Отключение движения/коллизии (аналогично `UHidingComponent::EnterHidingSpot()`).
4. `UHidingComponent::SetHiddenExternally(true)` — наземные монстры не обнаруживают (переиспользует ветку укрытий `ABaseMonster::IsPlayerVisible()`/`IsHiddenInSpot()`).

### 7.3 `DropFromHook()`

Восстанавливает коллизию, переключает `MovementMode` на `MOVE_Falling` (падает), `SetHiddenExternally(false)` — обнаружение возобновляется немедленно.

## 8. Чернильное зрение

Почему это нужно: Наездница лишена пассивной навигации «с закрытыми глазами» (нет глазомера Реднека, нет огонька Священника). Чернильное зрение — её «второе дыхание» в темноте: способ ориентироваться, когда глаза закрыты, не открывая их по-настоящему и не привлекая монстров. Способ безопасен — ровно так же, как Воспалённое зрение Священника (§8.4) — и по дизайну должен зависеть от расхода отдельного ресурса «чернила», а не быть бесплатным (см. §8.5, пока не реализовано).

### 8.1 Эффект

- Полноэкранный постпроцесс `M_InkVision`: стенсильные силуэты монстров + контур глубины сцены + анимация чернильных капель.
- `SetBlindedByAbility()` — персонаж считается слепым для системы обнаружения (`IsEyesClosed()` = эффективно true) без реального вызова `CloseEyes()`/`OpenEyes()` (нет дыхательной мини-игры, нет риска мгновенной смерти при «открытии»).
- `SetEyesClosedDarknessSuppressed()` — стандартный эффект темноты закрытых глаз (`EyesClosedPostProcessComp`) подавлен, пока активно чернильное зрение (иначе бы давил свой же постпроцесс).

### 8.2 Параметры

| Параметр | Значение | Где |
|---|---|---|
| `VisionDuration` | 10с | `UInkVisionComponent` |
| `VisionCooldown` | 15с | `UInkVisionComponent` |
| Клавиша | **V** | `ARiderCharacter::SetupPlayerInputComponent()` |

### 8.3 Жизненный цикл

`ToggleVision()` → включить (если `bCanUseVision`) / досрочно выключить (если `bIsVisionActive`) → таймер `VisionDuration` → `EndVisionEffect()` → таймер `VisionCooldown` → `bCanUseVision = true`.

### 8.4 Связь с «Огоньком на пальцах» Священника

Оба эффекта функционально одинаковы (силуэты, нет обнаружения). Визуальное решение общее (Custom Depth/Stencil + постпроцесс-материал поверх кадра), только цвет разный: чернильное — чёрно-белое/де-сатурированное, огонёк — тёплый красно-оранжевый (`FLinearColor(1.0, 0.45, 0.15)`). Общая система пока **не реализована** (отложено); `M_InkVision` — отдельная заглушка.

Чернильное зрение безопаснее по своей природе: как и Воспалённое зрение Священника (не
Огонёк, который лишь читает `IsEyesClosed()` и не меняет обнаружение сам по себе), оно
полностью заменяет восприятие персонажа собственным эффектом через `SetBlindedByAbility()`,
без дыхательной мини-игры и без риска мгновенной смерти при «открытии» — это тот же класс
гарантированной безопасности, что у Священника, просто другой визуальный язык
(`06-common-character-techniques.md` §6).

### 8.5 Ресурс «чернила» — задумано, не реализовано

По дизайну чернильное зрение должно расходовать отдельный ресурс («чернила»), а не быть
бесплатной способностью на одном лишь кулдауне — так же, как кадило тратит топливо, а
Реднек тратит `MoonshineStock`. Сейчас это **не реализовано**: `UInkVisionComponent`
ограничен только `VisionDuration`/`VisionCooldown` (§8.2) — способность доступна снова
ровно через фиксированное время, независимо от того, сколько раз и насколько долго она
уже использовалась.

**Открытые вопросы:**
- Единицы измерения «чернил» и стартовый/максимальный запас — по аналогии с РЕЗЕРВ/БАК
  масла (§6.2) или с единым конечным `MoonshineStock` Реднека?
- Траты: фиксированная порция за один тоггл (как глоток самогона, `PersonalDrinkCost`),
  или постепенный расход по ходу активного времени (как бак кадила во время боя)?
- Пополнение: ручная доливка игроком (как `RefillCenser()`), подбор предметов на уровне,
  или вообще без пополнения (одноразовый расходуемый запас на весь забег)?
- Сосуществует ли этот ресурс с текущим `VisionCooldown`, или кулдаун должен уйти совсем,
  оставив только ограничение по запасу «чернил»?

## 9. Экстренная абилка — Святой взрыв

Почему это нужно: предохранитель сценария «окружили толпой вслепую». Гарантированное AoE-убийство ценой всего топлива бака — одноразовый выход из безвыходной ситуации.

Это и есть «плеснуть маслом из кадила, чтобы разом уничтожить монстров вокруг» — весь бак
расходуется единовременно (п. 7 ниже), кадило после этого гаснет, убийство гарантированное
в радиусе. Текущий радиус уже зафиксирован в коде как `HolyExplosionRadius`=500 (§9.2) —
**открытый вопрос:** подтвердить это значение на геймдизайн-ревью как финальное для
ощущения «уничтожить монстров вокруг одним плеском», а не просто стартовая цифра для PIE.

### 9.1 Последовательность

1. **X** → `TryHolyExplosion()`
2. Guard-проверки (все должны пройти): кадило экипировано, `FuelRemaining >= HolyExplosionMinFuel`=5, не верхом, не в панике, таймер `HolyExplosionTimerHandle` не активен.
3. `LightUp()` кадила (если потушено).
4. `LaunchCharacter(0, 0, HolyExplosionJumpVelocity=500)` — прыжок вверх («замах»).
5. Таймер `HolyExplosionDelay`=0.8с → `ResolveHolyExplosion()`.
6. Sphere overlap радиуса `HolyExplosionRadius`=500: все живые `ABaseMonster` в радиусе → убийство через `UCenserDamageType`.
7. Бак обнуляется, кадило гасится (`PendingHolyExplosionCenser`).

### 9.2 Параметры

| Параметр | Значение |
|---|---|
| `HolyExplosionMinFuel` | 5.0 |
| `HolyExplosionRadius` | 500 (> `HolyAuraRadius`=220) |
| `HolyExplosionDelay` | 0.8с |
| `HolyExplosionJumpVelocity` | 500 |

## 12. Взаимодействие с другими механиками

| Механика | Поведение при пересечении |
|---|---|
| **Паника** | Посадка заблокирована (`!bIsPanicking` guard в `CanMountMonster()`). Верхом: удар → сброс без паники (явно подавлено в `ABaseMonster`, чтобы не было двойного наказания) |
| **Капкан** | Посадка заблокирована (`!bIsTrapped`). Верхом на монстре: монстр замирает 3с → принудительный Dismount |
| **Укрытие (HidingComponent)** | Крючок реиспользует `SetHiddenExternally()` — тот же путь, что физическое укрытие в шкафу/ящике |
| **Eye Peek / Chase-атака монстра** | `IsTargetInLight()` проверяется до `TryStartNaskokAttack()` — монстр в зоне кадила не наносит удар |
| **Святой взрыв** | Заменяет «аварийное раскидывание», обсуждавшееся для Rider (Fase 1.2 роадмапа) — убийство в радиусе, а не физический толчок |
| **UProbeComponent** | Создаётся в `ABaseCharacter` для всех героев, в том числе Наездницы (G — прощупывание вперёд). Не специфичен для неё |
| **Mental Trail / система «видно сквозь слепоту»** | Чернильное зрение — один из трёх запланированных потребителей общей системы Custom Depth/Stencil (наряду с огоньком Священника и Mental Trail Реднека). Пока реализовано как отдельный постпроцесс `M_InkVision` |
