# Правила: Атака / Стелс / Паника / Орда — сверочный документ (ЧЕРНОВИК)

> Собрано по схеме Милы (ручной рисунок, несколько кусков). Это ПЕРВАЯ версия для
> сверки — не финальная. Ничего из этого ещё не сравнивалось построчно с кодом.
> Отмечено ⚠️ там, где я не уверена, что прочитала/поняла правильно.

## 1. Верхний уровень

Игрок на карте, где есть монстры → развилка по состоянию глаз:
- **С открытыми глазами** → раздел 2
- **С закрытыми глазами** → раздел 3

## 2. С открытыми глазами

- Игрок **вне зоны видимости монстра** → монстр занимается своими делами (ничего не происходит).
- Игрок **в зоне видимости монстра** → монстр начинает преследование игрока (обычный сценарий погони).

⚠️ На маленьком общем скрине в этой же ветке мелькали ещё пункты («продолжает идти в стелс, пока не наткнулась», что-то про обнаружение через фокус/прицеливание, случайное столкновение с монстром) — на присланном крупном куске их уже не было, только эти два блока. Это простое двухблочное дерево — вся ветка «открытые глаза», или там раньше было что-то ещё, что ты сейчас не стала пересылать?

Судя по всему, эта ветка = уже существующая стабильная механика (`IsPlayerVisible`/`IsPlayerLookingAtMonster` → обычный Chase). Менять здесь скорее всего ничего не нужно.

## 3. С закрытыми глазами — три пути

### 3a. «Прощупывание / Стелс» — НЕ настроено, отдельная будущая механика

Игрок либо медленно идёт вперёд с вытянутыми руками, либо ощупывает пространство перед собой стоя на месте (та же функция, просто без движения). Впереди оказывается:
- **Монстр** → монстр рычит, идти дальше нельзя.
  - Игрок продолжает щупать рычащего монстра → вызывает раздражение монстра → **монстр бьёт** (та же логика разрешения удара, что в разделе 4 — присед+закрытые глаза могут увернуть) → промах уводит в скан пространства в раздражении (жёлтый, циклично, раздел 4a), попадание уводит в раздел 5 (гарантированный урон → призыв орды). Не «раздражение → просто сканирует», а «раздражение → удар → (промах→скан / попадание→урон)».
  - Игрок ждёт, пока монстр перестанет рычать → можно прощупать ещё раз.
- **Пустота** → проход безопасен, можно идти вперёд.
- **Стена / предметы** → соответственно, препятствие.

(Это, судя по всему, будущая механика «красться», отдельно упомянутая ранее как 1.2b — ещё не реализована, трогать не нужно. Подтверждено.)

### 3b. «Подглядывает через ПКМ» (существующая функция прицела/фокуса)

- Игрок **вне зоны видимости монстра** → монстр не обнаруживает.
- Игрок **в зоне видимости монстра** → монстр обнаруживает → монстр начинает преследование игрока.
  - Монстр теряет след — игрок прячется или маскируется, закрыв глаза.
  - Монстр настигает игрока успешно → монстр наносит удар → раздел 4.

### 3c. Случайное столкновение (не в стелсе/прощупывании)

Игрок врезается случайно в монстра на бегу/ходьбе/прыжке (НЕ находясь в стелсе/прощупывании) → вызывает раздражение монстра → монстр сканирует пространство какое-то время в раздражении.

## 4. Разрешение удара монстра («монстр наносит удар»)

В момент реального удара смотрим на состояние игрока:

| Состояние игрока в момент удара | Результат |
|---|---|
| Присел И закрыл глаза | **Уворот** — игрок невидим для монстра → монстр сканирует пространство в раздражении (жёлтый) → см. раздел 4a |
| Присел, но глаза открыты | **Гарантированный урон** (присед один не спасает при открытых глазах) → раздел 5 |
| Закрыл глаза, но не присел | **Гарантированный урон**, если игрок в зоне, куда достаёт удар (закрытых глаз одних недостаточно) → раздел 5 |

Это уже реализовано в коде (`TryStartPanicStrike`/`DoesEyePeekAttackConnect`+`IsEyesClosed`) и подтверждено в PIE — судя по схеме, реализовано верно, менять не нужно.

### 4a. Общая модель состояния «Раздражение» (единый цикл, переиспользуется в 3a/4a/5) — ФИНАЛЬНАЯ, подтверждена

Каноническая формула (подтверждена Милой, включая разбор конфликта):

> Монстр триггернулся в раздражение → бьёт:
> 1. **Промах** → стоит, сканирует пространство (если игрок не виден) → успокаивается. **Конец — этот конкретный монстр выбывает из эпизода НАВСЕГДА, больше попыток не получает.**
> 2. **Попадание** → призывает новую волну → тут же бьёт снова (заход не заканчивается одним ударом).

«Раздражение» — одно общее состояние-цикл на КАЖДОГО монстра по отдельности, в которое ведут разные триггеры (прощупывание рычащего монстра — 3a; провокация после уворота — ниже; участие в волне призыва — раздел 5). Промах = разовая попытка была, монстр этот эпизод больше не трогает игрока. Попадание = монстр остаётся в цикле и бьёт снова при первой возможности.

**Пояснение (снимает более ранний кажущийся конфликт с PIE-тестом 1.2d, п.6):** «один удар на монстра» из более раннего теста означало не «монстру разрешён ровно один удар за весь эпизод, точка», а «одна попытка за один заход — и если это ПРОМАХ, на этом для него всё кончается». Если попадание — заход не заканчивается, монстр зовёт волну и бьёт снова. Противоречия нет, просто более раннее тестирование не проверяло сценарий повторного попадания тем же монстром.

Применительно конкретно к этому разделу (после уворота, монстр в раздражении сканирует):
- Игрок замер или отполз, пока идёт «кулдаун» раздражения → через время монстр возвращается к своим делам (зелёный, конец цепочки — это и есть исход 1 «промах» из формулы выше).
- Игрок выдал себя каким-либо способом, пока раздражение не прошло (начал прощупывать/потрогал раздражённого монстра с закрытыми глазами, или сам двинулся на него; либо открыл глаза/подсмотрел через ПКМ в зоне видимости монстра) → монстр бьёт заново (новый заход по формуле выше — снова промах/попадание).

## 5. «Призыв» (волна) — после любого «гарантированного урона» из разделов 3b/4/4a — ФИНАЛЬНАЯ, подтверждена

- Гарантированный урон → **Призыв** (волна).
- Карта НЕ открытый мир — на локации фиксированный, известный набор монстров. Поэтому каждый новый призыв триггерит **ВСЕХ ОСТАЛЬНЫХ подходящих монстров локации на одну попытку удара каждому — включая самого призывающего** (не только «новых» — это не отдельный набор, это просто волна для всех, кто ещё не выбыл).
- Монстры, ещё не добравшиеся до точки первой поимки, начинают двигаться **к этой фиксированной точке** (НЕ к живому текущему положению игрока — см. обоснование выше: монстр не может преследовать то, чего не видит с закрытыми глазами игрока). Монстры, которые уже там (или уже били раньше и попадали), участвуют в этой же волне на месте.
- Каждый участвующий в волне монстр наносит свою одну попытку удара по формуле раздела 4a:
  - **Промах** → выбывает из эпизода навсегда (сканирует → успокаивается / либо просто уходит, если игрок вне видимости).
  - **Попадание** → урон → сам монстр призывает СЛЕДУЮЩУЮ волну и тут же бьёт снова (продолжает участвовать).
- Обнаружение, если игрок оказался В зоне видимости монстра (глаза открыты) в момент промаха → это уже честная видимость, раздел 2 — монстру разрешено обычное «живое» преследование.

Естественное ограничение каскада: волны не бесконечны, потому что при каждой волне участвуют только монстры, ещё не промахнувшиеся за этот эпизод (выбывшие раз и навсегда) — а игрок в конце концов почти всегда либо успешно увернётся хоть раз (закрыв глаза и присев/отойдя — и тогда конкретный этот монстр выбывает), либо умрёт от наросшего урона. Отдельного искусственного счётчика/лимита не нужно — миссоватость сама останавливает эскалацию по мере того, как монстры один за другим выбывают.

## 6. Паника (стан) — от «Призыва орды» / добивающего удара — ОБНОВЛЕНО (финальная модель, подтверждена)

- Первый удар, который попал (по таблице раздела 4) → **Стан (Паника — для игрока)** → игрок падает на пол. Не важно, были глаза открыты или закрыты в момент именно этого удара — паника запускается в любом случае.
- Пока идёт мини-игра дыхания (`bIsPanicking == true`):
  - **Закрыл глаза** → любой добивающий удар орды (раздел 5) промахивается. Присед роли не играет — персонаж и так физически лежит на полу (`PlayKnockdownAnimation()`), требовать ещё и нажатие приседа поверх этого не имеет смысла.
  - **Глаза открыты**, и добивающий удар орды (от того же или другого монстра волны) попал → **смерть**.
  - **Сам открыл глаза нажатием** во время паники → мгновенная смерть — уже существующий, не меняется (`OpenEyes()`, при валидном `BlindEncounterMonster`).
  - **Игра в дыхание** (мини-игра, ритм-биты — единственный оставшийся здесь таймер, не меняется):
    - Провал (не успел нажать вовремя слишком много раз, `PanicMeter` дошёл до максимума) → форсированное открытие глаз → ролл на ближайшего монстра: есть кто-то рядом → смерть; никого рядом → повезло, выжил. Не меняется.
    - Успех → см. ниже.
  - ~~Таймер «не закрыл глаза — умер сам по себе через N секунд после начала паники»~~ — **убран целиком**. Дублировал/подменял добивающий удар произвольным отсчётом времени, не привязанным к реальному наличию угрозы — мог убить, даже если причинный монстр уже погиб (например, сгорел на солнце), а других поблизости нет; либо не убить вовремя, если глаза на момент разовой проверки таймера случайно оказались закрыты, а потом снова открылись. Добивающий удар (при реальном попадании) и `OpenEyes()` (при осознанном открытии) вместе полностью покрывают исход «открытые глаза в панике опасны», без произвольного таймера.
  - Успех в игре дыхания:
    - Персонаж встаёт (текущее поведение — `RecoverFromKnockdown()` поднимает автоматически, как только паника разрешилась успешно).
    - *(Задел на будущее, зависит от ещё не реализованной механики 1.2f «явная кнопка встать» — сейчас недостижимо в игре, т.к. персонаж поднимается автоматически)*: если игрок в будущем сможет осознанно остаться лежать после победы в мини-игре (`bIsPanicking` уже `false`), с открытыми глазами, и его достанет добивающий удар — это **не мгновенная смерть**, а повторный вход в панику (`EnterPanicState()` вызывается заново, как при свежей поимке) — по кругу, пока не встанет или не умрёт иначе.
  - Попытка двинуться (дёрнуться) во время паники → резкий скачок шкалы паники (наказание за нетерпение) — уже существующая механика, не меняется.
